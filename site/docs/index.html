Documentation

Everything auto-form-filler does. Install it, map your fields, and decide whether it submits for you.

auto-form-filler reads the query string of the current page and fills the fields of a form with it. This page covers every option and method.

Install

With npm, or any package manager:

npm install @cnaallotey/auto-form-filler

It ships ES module and CommonJS builds with TypeScript types, so both import and require work.

Or with a script tag, which adds a global AutoFormFiller:

<script src="https://unpkg.com/@cnaallotey/auto-form-filler/dist/index.umd.js"></script>
<script>
  AutoFormFiller.autoFillForm({ formSelector: '#signup-form' });
</script>

Quick start

Call autoFillForm on the page that has the form:

import { autoFillForm } from '@cnaallotey/auto-form-filler';

autoFillForm({ formSelector: '#signup-form' });

Then link to the page with values in the query string:

https://example.com/signup?email=ada%40example.com&firstname=Ada&company=Acme

When the page loads, the email, first name and company fields in #signup-form are filled in. Encode values with encodeURIComponent when you build links, so characters like @, & and % survive.

How values are filled

Each query parameter is looked up in the field mappings. If it has a mapping, the first matching field inside the target form is filled. Fields outside the form are only used when they’re attached to it with the form attribute. Parameters without a mapping are ignored.

FieldWhat happens
Text, email, tel, number, textarea and other inputsThe value is set as written.
Checkboxtrue, 1, yes or on checks it. false, 0, no or off unchecks it. Case doesn’t matter. Any other value is skipped.
Radio buttonThe radio in the same group whose value matches exactly is checked. If none match, it’s skipped.
SelectThe option whose value matches exactly, or whose label matches ignoring case, is selected. If none match, it’s skipped.

After a field is filled, input and change events are fired on it so your own listeners and frameworks see the new value. Skipped fields don’t count as filled and never trigger auto-submit on their own.

If a parameter appears more than once, the last value is used.

Field mappings

A mapping connects a query parameter to a CSS selector. A selector can list several alternatives separated by commas. They’re tried in order and the first one that finds a field in the form wins.

Built-in mappings

ParameterSelectors
emailinput[name="email"], input[type="email"], #email
nameinput[name="name"], input[name="fullname"], #name, #fullname
firstnameinput[name="firstname"], input[name="first_name"], #firstname
lastnameinput[name="lastname"], input[name="last_name"], #lastname
phoneinput[name="phone"], input[type="tel"], #phone
companyinput[name="company"], input[name="organization"], #company
utm_sourceinput[name="utm_source"], #utm_source
utm_mediuminput[name="utm_medium"], #utm_medium
utm_campaigninput[name="utm_campaign"], #utm_campaign

Adding your own

Pass fieldMappings to add parameters or replace a built-in one. Your mappings are merged with the built-in ones. 

autoFillForm({
  fieldMappings: {
    plan: 'input[name="plan"]',            // radio group
    country: 'select[name="country"]',
    message: 'textarea[name="message"]',
    email: '#work-email',                  // replaces the built-in email mapping
  },
});

Options

All options are optional.

OptionDefaultDescription
formSelectorstring 'form' Selector for the form to fill. The first match is used.
fieldMappingsRecord<string, string> {} Extra or replacement mappings from parameter to selector. See Field mappings.
autoSubmitboolean false Submit the form after at least one field is filled. Read Security before turning this on.
submitDelaynumber 1000 Milliseconds to wait between filling and submitting.
customSubmitFunction(form, data) => void | Promise<void> None Called instead of submitting the form natively, for example to send it with fetch.
onBeforeSubmit(form, data) => boolean Returns true Called before auto-submitting. Return false to cancel.
onAfterSubmit(form, data) => void None Called after the form is submitted, or after customSubmitFunction finishes.
onError(error: Error) => void Logs to the console Called when filling or submitting fails, or when validation blocks a submission.
observeDOMbooleanNew in 1.2.0 false Watch the page and try again when the form isn’t there yet. See Forms that render late.
domObserverTimeoutnumberNew in 1.2.0 10000 Stop watching after this many milliseconds.
maxDOMObserveRetriesnumberNew in 1.2.0 10 Stop watching after this many attempts.
debugboolean false Log each step to the console with an [AutoFormFiller] prefix.

In the callbacks, data holds only the parameters that were actually filled, for example { email: 'ada@example.com', plan: 'team' }.

Methods

autoFillForm(config?)

Creates a filler and fills the form as soon as the page is ready. Returns the AutoFormFiller instance. It’s the same as AutoFormFiller.init(config).

new AutoFormFiller(config?)

Creates a filler without filling anything. Use this when you want to decide when to fill.

import AutoFormFiller from '@cnaallotey/auto-form-filler';

const filler = new AutoFormFiller({ autoSubmit: false });
openSignupModal();
filler.fillForm('#modal-signup');

filler.fillForm(formSelector?)

Fills the form matching formSelector, or config.formSelector if you leave it out. Returns true if at least one field was filled. Calling it again before a pending auto-submit runs replaces that submission rather than adding a second one.

filler.destroy()New in 1.2.0

Stops watching the page and cancels any fill or auto-submit that hasn’t happened yet. After this the instance does nothing. Call it when the page or component that owns the form goes away.

Auto-submit

With autoSubmit: true, this happens submitDelay milliseconds after a field is filled:

  1. onBeforeSubmit(form, data) runs. If it returns false, nothing else happens.
  2. If you set customSubmitFunction, it’s called and the form isn’t submitted natively. When it returns a promise, onAfterSubmit runs once it resolves and onError runs if it rejects.
  3. Otherwise the form is submitted with form.requestSubmit(), the same as pressing its submit button. Browser validation runs and your submit handlers fire. If validation stops the submission, onError is called instead of onAfterSubmit. In browsers without requestSubmit, form.submit() is used. 
autoFillForm({
  autoSubmit: true,
  submitDelay: 1500,
  onBeforeSubmit: (form) => form.checkValidity(),
  customSubmitFunction: async (form) => {
    const response = await fetch(form.action, { method: 'POST', body: new FormData(form) });
    if (!response.ok) throw new Error(`Signup failed: ${response.status}`);
  },
  onAfterSubmit: () => showThanks(),
  onError: (error) => showError(error.message),
});

Forms that render late

In single-page apps the form often isn’t on the page when your script runs. With observeDOM: true, if the form or its fields aren’t found, the library watches the page for new elements and tries again, waiting half a second after changes settle.

It stops watching as soon as any of these happens:

  • at least one field is filled
  • it has tried maxDOMObserveRetries times
  • domObserverTimeout milliseconds have passed
  • you call destroy()

It doesn’t watch at all when the URL has no query parameters.

autoFillForm({
  formSelector: '#signup-form',
  observeDOM: true,
  domObserverTimeout: 15000,
  maxDOMObserveRetries: 20,
});

React and other frameworks

  • React
  • Next.js
  • Vue
  • Svelte
  • Angular

Values are set the way a browser sets them when someone types, then input and change events are fired. Controlled inputs in React, and bound inputs in Vue, Svelte and similar libraries, update their state from those events.

Create the filler after the form is mounted and destroy it when the component unmounts: 

import { useEffect } from 'react';
import { autoFillForm } from '@cnaallotey/auto-form-filler';

export function SignupForm() {
  useEffect(() => {
    const filler = autoFillForm({ formSelector: '#signup-form' });
    return () => filler.destroy();
  }, []);

  return <form id="signup-form">{/* fields */}</form>;
}

If the form appears after data loads, add observeDOM: true instead of waiting for it yourself.

Security

Anyone can write a link to your page with any values in it. Treat every pre-filled value as untrusted input, the same as something a visitor typed.

  • Be careful with autoSubmit. Opening a link submits the form from the visitor’s browser, with their cookies and session, using values chosen by whoever wrote the link. Only use it where an unintended submission is harmless, such as a newsletter or lead form.
  • Don’t map sensitive fields. Never fill passwords, payment details, or fields that change an account, like email or payout details on a settings page.
  • Keep personal data out of links you publish. Query strings end up in browser history, server logs and analytics. Pre-filling an email is fine in a link sent to that person, not in a public one.
  • Validate on the server, as you would for any form.

When nothing is filled

Turn on debug: true and check the console. The usual causes:

  • The form isn’t there yet. The console shows “Form not found”. Use observeDOM: true, or call fillForm() after the form renders.
  • The parameter has no mapping. Only parameters in the mappings are used. Add one with fieldMappings.
  • The field is outside the target form. Check formSelector, or attach the field with form="your-form-id".
  • The value doesn’t fit. Radio and select values must match an option, and checkboxes only take yes/no style values. The console names the value that was skipped.
