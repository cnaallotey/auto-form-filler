    How it works

    One link, one filled-in form. Each value in the query string lands in the matching field, with the events your framework listens for.

    Install it Point it at your form Share a link Submit it for them

    Install it. One small package with no dependencies, or a single script tag.

    npm install @cnaallotey/auto-form-filler
    <script src="https://unpkg.com/@cnaallotey/auto-form-filler/dist/index.umd.js"></script>

    Point it at your form. Turn on matchByName and every field whose name matches a parameter is filled. No mappings to write.

    import { autoFillForm } from '@cnaallotey/auto-form-filler';

autoFillForm({
  formSelector: '#signup-form',
  matchByName: true,
  allow: ['email', 'plan', 'role', 'utm_*'],  // optional
});

    Share a link. Build it with buildPrefillUrl so every value comes back exactly. Whoever opens it sees the form already filled in.

    buildPrefillUrl('https://example.com/signup', {
  email: 'ada@example.com',
  plan: 'team',
});

    example.com/signup?email=ada%40example.com&plan=team

    Work emailada@example.com
    PlanTeam

    Submit it for them, if you want. With autoSubmit the form is sent like a click on its button, so validation and your handlers still run.

    autoFillForm({
  autoSubmit: true,
  submitDelay: 1500,
  onAfterSubmit: () => showThanks(),
});

    Anyone can write a link to your page, so only auto-submit forms where an unintended submission is harmless. Add cleanUrl: true to take personal details out of the address bar once they’re filled. Read the security notes.

    New in 1.3

    Campaign values that survive the visit. Visitors land on one page and sign up on another. persist keeps their UTM values until they reach the form.

    • Remembers what you list

      Run it on every page with persist: ['utm_*']. Matching values are saved for the tab, or across visits with persistStorage: 'local'.

    • Fills them on the form page

      Hidden fields get the saved values. A value in the current link always wins.

    • Only what you allow

      Use allow to list which parameters can fill fields or be saved. Everything else is ignored.

    1. example.com/blog?utm_source=newsletter&utm_campaign=spring Saved utm_source and utm_campaign
    2. example.com/pricing Still remembered
    3. example.com/signup Filled 2 hidden fields: newsletter, spring

    Single-page apps

    Forms that load late, handled. Turn on observeDOM and the library waits for the form, fills it, then stops watching.

    • Waits for the form

      Tries again as new elements appear, half a second after the page settles.

    • Stops on its own

      After the form is filled, after 10 tries or after 10 seconds. All three are configurable.

    • Cleans up when you ask

      Call destroy() when the component unmounts and nothing runs after it.

    Field types

    Every kind of field. Values that don’t fit are skipped rather than guessed, so a bad link can’t tick the wrong box.

    Text fields

    firstname=Ada

    Set as written. Covers text, email, phone, number and textareas.

    Checkboxes

    newsletter=yes

    yes, true, on or 1 checks it. no, false, off or 0 unchecks it. Repeat the parameter to check several in a group.

    Radio buttons

    plan=team

    Checks the button in the group whose value is team.

    Selects

    role=Engineer

    Picks the option with that value, or that label ignoring case. Repeat the parameter for multi-selects.
